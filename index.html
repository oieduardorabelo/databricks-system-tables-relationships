Key join paths

    Account vs region scope

    Understanding scope is essential to avoid missing data or writing misleading queries.

    Databricks Account
    • Metastore: us-west-2
      • system.billing.usageglobal - all regions
      • system.compute.warehousesregional - us-west-2 only
      • system.query.historyregional - us-west-2 only
    • Metastore: eu-west-1
      • system.billing.usageglobal - all regions
      • system.compute.warehousesregional - eu-west-1 only
      • system.query.historyregional - eu-west-1 only

    Global tables aggregate data from all workspaces across all regions in the account, regardless of which metastore you query from. This includes system.billing.usage, system.billing.list_prices, and system.access.workspaces_latest.

    Regional tables expose data only from workspaces in the same region as the metastore you are querying from. This includes system.compute.warehouses, system.compute.warehouse_events, system.query.history, and system.access.audit (workspace-level events).

    Best practices for querying system tables

    Best practiceDetail
    ✅ Filter early on date columnsThese tables can hold months of data. Always apply a WHERE usage_date >= ... or WHERE event_time >= ... predicate before aggregating to avoid full table scans.
    ✅ Isolate warehouse chargesThe billing.usage table contains records for all Databricks products. For SQL warehouse cost analysis, filter to billing_origin_product = 'SQL'.
    ✅ Warehouses as a slow-changing dimensionEach configuration change creates a new row. To get the current configuration: WHERE delete_time IS NULL combined with QUALIFY ROW_NUMBER() OVER (PARTITION BY warehouse_id ORDER BY change_time DESC) = 1.
    ✅ Account for billing correctionsThe usage table supports RETRACTION and RESTATEMENT records. Always aggregate with SUM(usage_quantity). RETRACTION records carry negative quantities that cancel out the original.
    ✅ Use struct field syntax for joinsIn Databricks, access struct fields with dot notation: usage_metadata.warehouse_id.
    ✅ Set skipChangeCommits = true for streamingIf you stream from system tables, this prevents the job from failing when Databricks performs deletes on the table.

    Key takeaways

    • System tables are in the system catalog, governed by Unity Catalog, and read-only.
    • Global tables (system.billing.usage, system.billing.list_prices) contain data from all regions. Regional tables (system.compute.*, system.query.history) contain data from the current metastore's region only.
    • The four schemas this course focuses on: billing, compute, query, and access.
    • Access requires a UC-enabled workspace. Account admins have access by default; other users need explicit grants.
    • Filter on date columns early, isolate SQL usage with billing_origin_product = 'SQL', and use SUM(usage_quantity) to handle billing corrections correctly.
